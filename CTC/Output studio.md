# CTO CostControl — Codex Master Implementation Specification

## Purpose

Use this document as the single implementation baseline for the CTO CostControl application.

The objective is to turn the current application into a top-management cost intelligence and project-control command center that:

- reads the existing monthly project JSON history already generated by the app,
- compares multiple months for the same project,
- compares multiple projects against one another,
- compares project history across all available months,
- provides portfolio-level management outputs,
- supports drill-down from portfolio to project to month to WBS to cost code to transaction,
- keeps charts and tables fully synchronized,
- supports management-ready downloadable reports,
- uses SAMCO branding,
- contains no visible references to machine learning, AI, model confidence, automated learning, inference, or similar terminology in management-facing screens or downloadable reports.

Do not redesign or replace the existing workbook reader, project identity workflow, JSON publication logic, or historical JSON storage unless a change is required to expose data to this dashboard.

Preserve all existing working project behavior.

---

# 1. NON-NEGOTIABLE IMPLEMENTATION RULES

1. The dashboard must be data-driven.
2. Never hard-code project names such as THE BIG, GLORIA, Bridge, LMD, or future projects into chart logic.
3. Never hard-code month lists beyond generic month/date parsing.
4. All project and month lists must be discovered from available JSON/history data.
5. All portfolio calculations must use the underlying values, not averages of already-calculated ratios.
6. Portfolio CPI must be:
   `SUM(EV) / SUM(AC)`
   and must never be a simple average of project CPI values.
7. Portfolio CV must be:
   `SUM(EV) - SUM(AC)`.
8. Portfolio VAC must be:
   `SUM(BAC) - SUM(EAC)`.
9. Missing values must remain missing/blank/not available.
10. Do not fabricate missing financial data.
11. All management-facing screens and exports must avoid any AI/ML terminology.
12. All chart values must be traceable to the source JSON/project/month.
13. Every major chart must have a related detailed table.
14. Every major table must be filterable, sortable and exportable.
15. Chart selection must update tables.
16. Table selection must update charts.
17. The selected state must be shared across the page.
18. Large tables must use virtualization or equivalent high-performance rendering.
19. The application must remain responsive on desktop, tablet and laptop resolutions.
20. The final design should feel like a professional executive cost-control application, not a generic admin dashboard.

# 6. KPI DEFINITIONS

Required portfolio/project KPI cards:

- Contract Value
- BAC / Total Budget
- Direct Budget
- Indirect Budget
- Earned Value (EV)
- Actual Cost (AC)
- Cost Variance (CV)
- CPI
- ETC
- EAC
- VAC
- Revenue
- Gross Profit
- Gross Profit %
- Cash In
- Cash Out
- Net Cash
- Cumulative Cash
- Progress %
- Project Count
- Green Project Count
- Amber Project Count
- Red Project Count

Core formulas:

```text
CV = EV - AC
CPI = EV / AC
VAC = BAC - EAC
Net Cash = Cash In - Cash Out
Cumulative Cash = cumulative Cash In - cumulative Cash Out
GP = Revenue - Actual Cost - recognized commercial burden when applicable
GP% = GP / Revenue
```

Do not invent ETC/EAC where the source does not provide or support them.

---

# 7. STATUS / RAG LOGIC

Use configurable thresholds.

Recommended defaults:

CPI:
- Green: `>= 1.00`
- Amber: `>= 0.95 and < 1.00`
- Red: `< 0.95`

CV:
- Green: positive or zero
- Amber: mildly negative inside configured tolerance
- Red: materially negative beyond tolerance

Forecast:
- Green: EAC <= BAC
- Amber: EAC moderately above BAC
- Red: EAC materially above BAC

Cash:
- Green: positive and stable
- Amber: deteriorating
- Red: negative or severe deterioration

Trend:
- Up arrow
- Flat arrow
- Down arrow

The application must show both:
- current status,
- direction of movement versus previous month.
